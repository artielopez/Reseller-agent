The installed compiled sources and registry release 2026.10.9 have these differences. The consent timeouts may be caused by them; that is a hypothesis until a corrected flow succeeds. No account eligibility conclusion follows from a timeout.

Only public dependency files are shared through a node_modules symlink.

Steps: record failing contract checks; prepare/verify the isolated runtime; try one fresh corrected sign-in; inspect the exact consent and resulting app controls; retain bounded evidence and clean up the callback process. No model call unless the separate usage checks pass. Do not wire this experimental runtime into production drafting or relax synthetic-only gates implicitly.

The initial read-only contract check failed both required-field assertions. Inspection identified the separate setup bundle, so the preparer now patches both the setup and normal auth entrypoints (four pinned files). `scripts/check-siwc-compat.mjs` then passed real offline invocation of both compiled login functions: stable host ID, IPv4 callback, unchanged scopes/resource, and fresh PKCE/state/nonce. Each invocation aborts before opening the browser and closes its local listener. The actual CLI then emitted the corrected request too.

One corrected live sign-in reached the same explicitly approved Reseller Agent consent and returned **Operation timed out** on OpenAI's page. No callback completed. The process was stopped and no listener remained on port 8080. These compatibility differences are real, but fixing them was insufficient; do not call them the proven timeout cause. The prepared runtime is not released for worker use. Keep the host file stable for any later supported retry, and stop repeated consent loops until provider guidance or a relevant change.

Lint and the standard suite passed: 220 tests, six optional skips. No application behavior changed; app build/browser suites were not repeated for these local diagnostic scripts.
